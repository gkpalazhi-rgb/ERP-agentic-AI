🏗️ System Architecture Layers
⚛️

Frontend — React + Vite

TypeScript SPA with Tailwind CSS. Serves chat interface, dashboards, and management pages at localhost:5173.

LoginPage DashboardPage InventoryPage VendorsPage LeavesPage PurchaseOrdersPage
🚀

Backend — FastAPI

Python REST API at localhost:8000. Handles auth, chat, CRUD endpoints with JWT-based RBAC and SQLAlchemy ORM.

main.py auth.py CORS JWT
🤖

Agent Core — agent.py

Orchestrates the full planning pipeline: clarification detection → semantic routing → LLM fallback → rule-based backup.

generate_plan() fallback_planner()
🧠

Intent Classifier

3-layer classifier: regex keyword rules → sentence-transformer semantic similarity → LLM. Caches 900+ inventory items + vendor names.

all-MiniLM-L6-v2 BERT cosine≥0.65
🔀

Semantic Router

Wraps the intent classifier + legacy keyword logic. Routes messages before touching the LLM, improving latency dramatically.

semantic_router.py
⚙️

Execution Engine

Iterates plan steps with RBAC enforcement, guardrails (vague item names, missing vendor), conditional branching, and audit logging.

execution_engine.py RBAC Guardrails
🔧

ERP Tools — tools.py

8 domain tools covering inventory, purchase orders, vendors, invoicing, leave applications and stock arrival verification.

8 tools tool_registry.py
📧

Email Service

Sends automated purchase order notifications to vendor emails via SMTP when a PO is created, with HTML template support.

email_service.py SMTP
🗄️

Database Layer

SQLAlchemy ORM with auto-migration and data backfill on startup. Supports both SQLite (dev) and PostgreSQL (prod).

SQLAlchemy SQLite PostgreSQL
🦙

LLM — Ollama

Local Ollama with llama3.2:3b model as last-resort planner. 25s timeout, lightweight retry with shorter prompt on failure.

llama3.2:3b localhost:11434 JSON mode
🧠 Intent → Tool Mapping
check_inventory
→ get_inventory(item)

Searches inventory by item name with fuzzy matching. Returns quantity or multi-match summary.

"how many amber bottles do we have" "show stock of arishtam"
create_purchase_order
→ create_purchase_order(item, qty, vendor)

Creates PO with auto-generated ID (YYMMDD-ITEMCODE-NNN). Triggers vendor email. Blocks vague items or missing vendor.

"buy 50 amber bottles from MedLife" "order 100 capsules"
get_po_status
→ get_po_status(po_id)

Resolves PO by exact ID, prefix match, or legacy numeric key. Calculates total cost from inventory MRP.

"status of PO 260324-AYU001-001" "track order 5"
generate_invoice
→ generate_purchase_invoice(po_id)

Generates a formatted .txt invoice file in the invoices/ directory with PO details and total cost.

"generate invoice for PO 260324" "make a bill for order 3"
get_vendors
→ get_vendors()

Returns full vendor directory: code, name, location, category, email.

"show all vendors" "who supplies bottles"
add_vendor
→ add_vendor(name, code, category, ...)

Registers a new supplier with optional email. Admin-only tool.

"add vendor Pharma Corp for capsules"
update_vendor
→ update_vendor(name, email)

Updates vendor contact info (email / price). Admin-only tool.

"update vendor email for MedLife"
apply_leave
→ apply_leave(reason, date, type)

Creates leave application. Parses natural language dates (tomorrow, 25th March). Supports Full Day / Half Day.

"apply leave tomorrow for fever" "take 1st half leave on Monday"
stock_arrival
→ update_inventory_stock(item, qty, po_id)

Cross-validates against a pending PO before updating. Marks PO as Delivered. Rejects duplicate arrivals.

"50 amber bottles arrived for PO 260324"

🛡️ Execution Guardrails
🚫

Vague Item Rejection

PO blocked if item name is "item", "those", "them", "stuff", etc. User prompted for specific name.

🏢

Mandatory Vendor Selection

PO blocked if no vendor specified. Returns live vendor list from DB with example prompt.

🔒

Stock Arrival Verification

Inventory update requires a valid pending PO. Duplicate arrivals rejected. Item cross-checked against PO.

❓

Clarification Loop

Missing required fields trigger a clarification question. Follow-up answers are merged with original query.
